2. WHAT ARE THE MODELS USED IN CLASSIFICATION?
================================================================================

DATASET CLASSIFICATION MODEL:
------------------------------
Type: Hybrid Rule-Based + Statistical Classification System
Approach: Multi-stage weighted scoring algorithm

Classification Categories:
  1. Financial (transactions, accounting, banking)
  2. Sales/Retail (products, customers, orders, e-commerce)
  3. Time-Series (temporal data with trends)
  4. Healthcare (medical records, diagnoses)
  5. Marketing (campaigns, leads, conversions)
  6. HR/Employee (workforce, payroll, attendance)
  7. Logistics/Supply Chain (shipping, inventory)
  8. Generic (fallback for unclassified data)

Classification Methodology:
  • Weighted keyword matching (strong/moderate/weak keywords)
  • Fuzzy matching for abbreviations and variations
  • Column combination analysis (semantic groups)
  • Value pattern detection (regex for currency, dates, codes)
  • Data type distribution analysis
  • Statistical feature analysis

Scoring System:
  • Strong keywords: 1.0 weight
  • Moderate keywords: 0.5-0.8 weight
  • Weak keywords: 0.3-0.4 weight
  • Confidence threshold: Minimum 0.3 for classification

AI MODEL FOR INSIGHTS:
----------------------
Model: Google Gemini 2.0 Flash Exp
Provider: Google AI (via google-genai library)
Purpose: Generating natural language insights, chat responses, and explanations

Fallback Strategy:
  • Primary: AI-generated insights using Gemini
  • Fallback: Statistical analysis when AI is unavailable
  • Hybrid: Combines statistical + AI insights for best results

5. WHAT ARE THE MODELS USED? WHAT IS THE WORKFLOW?
================================================================================

MODELS ARCHITECTURE:
--------------------

1. DatasetClassifier (backend/core/dataset_classifier.py)
   - Hybrid rule-based classification
   - Weighted keyword scoring
   - Pattern detection
   - Returns: type, confidence, features, suggestions

2. ColumnProfiler (backend/core/column_profiler.py)
   - Analyzes each column individually
   - Detects semantic types (currency, email, phone, etc.)
   - Computes statistics (mean, median, std, quartiles)
   - Returns: type, semantic_type, stats, missing_info, quality_score

3. RelationshipDetector (backend/core/relationship_detector.py)
   - Identifies correlations between columns
   - Detects foreign key relationships
   - Finds hierarchies (parent-child)
   - Returns: relationships, strength, type

4. QualityScorer (backend/core/quality_scorer.py)
   - Overall dataset quality score (0-100)
   - Column-level quality metrics
   - Identifies issues (missing data, duplicates, outliers)
   - Returns: overall_score, column_scores, issues

5. PreprocessingEngine (backend/core/preprocessing_engine.py)
   - Base engine for all preprocessing
   - Suggests operations based on data issues
   - Tracks changes with audit trail
   - Returns: suggestions, audit_trail, comparison

6. Domain-Specific Pipelines:
   - FinancialPipeline (currency normalization, transaction validation)
   - SalesPipeline (product ID standardization, quantity validation)
   - TimeSeriesPipeline (temporal ordering, frequency handling)
   - HealthcarePipeline (medical code validation)
   - GenericPipeline (standard cleaning operations)

7. InsightGenerator (backend/core/insight_generator.py)
   - Statistical insights (always available)
   - AI insights (when Gemini is enabled)
   - Generates recommendations
   - Returns: insights, confidence, evidence, visualizations

8. VisualizationRecommender (backend/core/visualization_recommender.py)
   - Recommends appropriate charts
   - Based on column types and relationships
   - Domain-aware suggestions
   - Returns: chart_type, columns, priority, rationale

9. ChartGenerator (backend/core/chart_generator.py)
   - Generates Plotly chart specifications
   - 17+ chart types supported
   - Responsive and interactive
   - Returns: plotly_json, layout, config

│

├─ Shows confidence score and reasoning

├─ Backend updates classification if changed
└─ Proceeds to preprocessing with confirmed type

Phase 4: PREPROCESSING
│
├─ Selects domain-specific pipeline
├─ Generates preprocessing suggestions
├─ User reviews and approves operations
├─ Applies selected operations sequentially
├─ Tracks each change in audit trail
├─ Computes before/after comparison
└─ Returns: cleaned_data, audit_trail, comparison

Phase 5: FEATURE EXTRACTION
│
├─ FeatureAnalyzer identifies important features
├─ Computes feature importance scores
├─ Detects feature interactions
└─ Returns: features, importance, interactions

Phase 6: INSIGHTS GENERATION

├─ StatisticalAnalyzer generates statistical insights
├─ (Optional) AI enhances with natural language insights

└─ Returns: insights[], recommendations[], evidence

Phase 7: VISUALIZATION
│
├─ VisualizationRecommender suggests charts
├─ Ranks recommendations by relevance
├─ ChartGenerator creates Plotly specifications
├─ User selects charts to display
└─ Returns: chart_json, interactive_config

Phase 8: DASHBOARD DISPLAY

├─ Frontend renders all insights

6. HOW IS PREPROCESSING DONE? WHAT ARE THE CRITERIA?
================================================================================

PREPROCESSING APPROACH:
-----------------------
EchoBI uses DOMAIN-SPECIFIC preprocessing pipelines tailored to each dataset 
type, ensuring context-aware data cleaning rather than generic operations.

CRITERIA FOR PREPROCESSING:
---------------------------

1. DATASET TYPE (Primary Criterion)
   Each dataset type has specialized preprocessing rules:
   
   Financial Datasets:
     ✓ Currency normalization (remove symbols, standardize decimals)
     ✓ Transaction date validation (remove future dates, min year 2000)
     ✓ Negative amount handling (flag or convert to absolute)
     ✓ Account number validation
     ✓ Duplicate transaction detection
   
   Sales/Retail Datasets:
     ✓ Product ID standardization (uppercase, remove spaces)
     ✓ Quantity validation (must be >= 0)
     ✓ Price consistency checks
     ✓ Customer data normalization
     ✓ Category standardization
   
   Time-Series Datasets:
     ✓ Temporal ordering (sort by timestamp)
     ✓ Frequency detection and alignment
     ✓ Missing timestamp handling
     ✓ Outlier detection in trends
     ✓ Seasonality consideration
   
   Healthcare Datasets:
     ✓ Medical code validation (ICD, CPT codes)
     ✓ PHI (Protected Health Information) flagging
     ✓ Date consistency (birth date < admission date)
     ✓ Vital signs range validation
     ✓ Diagnosis code normalization
   
   Generic Datasets:
     ✓ Standard missing value handling
     ✓ Duplicate row removal
     ✓ Basic outlier detection
     ✓ Type conversion where appropriate

2. DATA QUALITY ISSUES (Detected Automatically)
   
   Missing Values:
     • Threshold: Columns with >5% missing values trigger suggestions
     • Strategies: Drop, fill with mean/median/mode, forward/backward fill
     • Criterion: Column type and missingness pattern
   
   Duplicates:
     • Detection: Exact row duplicates
     • Action: Flag or remove based on user choice
     • Keep: First, last, or none
   
   Outliers:
     • Method: IQR (Interquartile Range) or Z-score
     • Threshold: Values beyond 1.5*IQR or 3 standard deviations
     • Action: Cap, remove, or flag
   
   Type Inconsistencies:
     • Numeric stored as text → Convert to float/int
     • Dates in multiple formats → Standardize to ISO format
     • Mixed types in column → Convert or split
   
   Range Violations:
     • Percentages outside 0-100
     • Negative values where impossible (age, quantity)
     • Future dates in historical data

3. COLUMN SEMANTIC TYPE (Guides Specific Operations)
   
   Currency Columns:
     ✓ Remove currency symbols ($, €, £, ₹)
     ✓ Standardize decimal places (2 for currency)
     ✓ Handle accounting format (parentheses for negative)
   
   Date/DateTime Columns:
     ✓ Parse multiple date formats
     ✓ Convert to ISO format (YYYY-MM-DD)
     ✓ Extract date components (year, month, day)
     ✓ Validate date ranges
   
   Email Columns:
     ✓ Validate email format (regex)
     ✓ Lowercase normalization
     ✓ Remove invalid entries
   
   Phone Number Columns:
     ✓ Remove formatting characters
     ✓ Standardize country codes
     ✓ Validate length
   
   Categorical Columns:
     ✓ Standardize case (uppercase/lowercase)
     ✓ Trim whitespace
     ✓ Map synonyms (M/Male/m → Male)
     ✓ Handle rare categories

4. STATISTICAL CRITERIA
   
   Skewness:
     • Highly skewed (>1 or <-1) → Suggest log transformation
     • Moderate skew (0.5 to 1) → Monitor for normalization
   
   Correlation:
     • High correlation (>0.9) → Suggest feature reduction
     • Negative correlation → Flag for review
   
   Variance:
     • Zero variance → Suggest column removal
     • Very low variance → Flag as potentially constant
   
   Cardinality:
     • High cardinality (>50 unique values) → Suggest grouping
     • Low cardinality (<5) → Suggest encoding strategy

5. DOMAIN KNOWLEDGE (Built-in Rules)
   
   Financial Domain:
     • Transactions should balance (debits = credits)
     • Account IDs should be unique per customer
     • Currency amounts need consistent precision
   
   Sales Domain:
     • Order dates should be <= delivery dates
     • Quantities should be positive integers
     • Product SKUs should follow consistent format
   
   Healthcare Domain:
     • Admission date should be >= birth date
     • Vital signs should be within medical ranges
     • Diagnosis codes should be valid ICD-10 codes


PREPROCESSING EXECUTION:
------------------------

1. SUGGESTION PHASE:
   - Analyzes data against all criteria
   - Generates ranked list of operations
   - Shows expected impact (rows/values affected)
   - User can select which operations to apply

2. EXECUTION PHASE:
   - Applies operations in dependency order
   - Tracks each change in audit trail
   - Computes statistics before and after
   - Stores reversible operations

3. VALIDATION PHASE:
   - Compares before/after metrics
   - Validates no critical data loss
   - Shows summary of changes
   - User can review and rollback if needed

4. AUDIT TRAIL:
   Each operation records:
   - Operation type and parameters
   - Columns affected
   - Rows before/after
   - Missing values before/after
   - Execution timestamp
   - User who applied it


TRANSPARENCY FEATURES:
----------------------
✓ Before/After comparison table
✓ Row-level change tracking
✓ Percentage of data modified
✓ Quality score improvement
✓ Reversible operations (rollback support)
✓ AI-generated summary of changes
